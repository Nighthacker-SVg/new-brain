# Attendx live implementation contract

The existing React office remains an explicitly labeled optional demo. The default Docker site becomes an authenticated live workspace. This document coordinates implementation; delivered limitations and verification belong in the README and readiness report.

## Services and ownership

- `server/core.mjs`, `server/api.mjs`, `server/test/core.test.mjs`: persistent SQLite control plane and HTTP API. Node 24 built-ins only. API listens on 9000, no host port. SQLite in `/data/attendx.db`. One API process owns durable jobs and starts the worker loop. Export `createServer(options)` for tests and start only when executed as main.
- `server/provider.mjs`, `server/worker.mjs`, `server/test/worker.test.mjs`: OpenAI-compatible model adapter and durable execution workflow. Imported by API; no additional listening port.
- `runner/server.mjs`, `runner/Dockerfile`, `runner/test/*.mjs`: private execution broker; Docker socket exists only here. Expose port 9100 inside the private Compose network, never to host. A shared `/control/runner-key` file authenticates requests; API creates random key if absent, runner reads it. API and runner mount the named control volume; runner read-only. No socket in API, frontend or agent execution containers.
- `src/LiveApp.tsx`, `src/live-api.ts`, `src/live.css`: authenticated frontend. Root main chooses this by default, existing App via `?demo=1`. Keep API wire types self-contained. Existing demo tests will target explicit demo mode.
- `src/motion.css` and optional isolated visual component: motion enhancements for existing/live classes, respect reduced-motion, no invented work telemetry.

## Added user requirement: multiple AI providers in Settings

Sidebar Settings contains AI providers with + Add provider. Owners can configure one or several OpenAI-compatible endpoints (OpenAI, OpenRouter, Groq, DeepSeek, Gemini-compatible, Ollama) and Anthropic. Each has label, type (`openai` or `anthropic`), baseUrl, model, secret API key, roles list, priority and enabled flag. Never return the full saved key; metadata only includes keyPresent and last4. Encrypt stored keys with AES-256-GCM using a random master key at `/data/master.key` (0600), outside SQLite; never mount data/master key into runner. No browser localStorage secrets. Owner-scoped routes: `GET/POST /api/providers`, `PATCH/DELETE /api/providers/:id`, optional `POST /api/providers/:id/test`. CSRF applies. Root owns `server/providers.mjs` provider registry and storage helpers to coordinate API and worker.

Provider module interface: `new ProviderRegistry(store,{masterKeyPath?,allowedHosts?})`, `.list(ownerId)` safe metadata, `.save(ownerId,input,id?)`, `.remove(ownerId,id)`, `.candidates(ownerId,role)` returns decrypted internal entries for worker only. Allowed default hosts: api.openai.com, api.anthropic.com, openrouter.ai, api.groq.com, api.deepseek.com, generativelanguage.googleapis.com, host.docker.internal, ollama. Extra hosts only administrator environment `ATTENDX_PROVIDER_HOSTS`. HTTPS required except exact allowed local Ollama hosts; reject credentials in URL, fragments, DNS/IP arbitrary hosts and redirects. Model calls use owner configs first, environment config fallback, bounded fallback (max2 providers per call), role mappings and conservative budget reservation per attempt. Never send one provider's credential to another. UI can explain custom endpoints require admin allowlisting. API implementer integrate registry routes with registry passed through options; worker consume options.registry if available. Anthropic adapter belongs provider.mjs worker implementer.

## Core module interface (all tenant-scoped)

Export `Store` class initialized with `{dbPath}`; instance `db` is node:sqlite DatabaseSync, `transaction(fn)`, `id(prefix)`, `now()`, `emit(ownerId, agentId, projectId, label, detail={})`, `state(ownerId)`.

Methods used by worker: `getProject(ownerId,id)`, `getAgent(ownerId,id)`, `getJob(id)`, `enqueue(ownerId,kind,projectId,agentId,payload={})`, `claimJob()` (atomically lease queued job; returns parsed object), `updateJob(id,patch)`, `addMessage(ownerId,projectId,agentId,role,content,evidenceIds=[])`, `addArtifact(ownerId,projectId,agentId,name,kind,content,mime='application/json')`, `addReview(ownerId,projectId,agentId,kind,title,details,payload={})`, `reserveBudget(ownerId,projectId,cents)`, `listMemories(ownerId,projectId)`. Add public core methods as needed, but notify dependent implementer. Synchronous store methods; async model/tool work outside transactions.

Schema: `users(id,name,email,password_hash,created_at)`, `sessions(id,user_id,csrf,expires_at)`, `projects(id,owner_id,name,brief,scope,stage,status,acceptance_criteria,repo_url,budget_cents,spent_cents,plan,plan_approved,created_at,updated_at)`, `agents(id,owner_id,name,role,template,persona,status,project_id,task,activity_label,stage,avatar,position_json,permissions_json,budget_cents,expires_at,created_at)`, `jobs(id,owner_id,kind,project_id,agent_id,status,payload_json,result_json,error,attempts,lease_until,created_at,updated_at)`, `messages(id,owner_id,project_id,agent_id,role,content,evidence_json,created_at)`, `artifacts(id,owner_id,project_id,agent_id,name,kind,content,mime,created_at)`, `reviews(id,owner_id,project_id,agent_id,kind,title,details,payload_json,status,created_at)`, `events(id,owner_id,agent_id,project_id,label,detail_json,created_at)`, `memories(id,owner_id,project_id,content,source_artifact_id,approved,created_at)`, `skills(id,owner_id,agent_id,version,instructions,status,evaluation_json,created_at)`, `schedules(id,owner_id,project_id,interval_minutes,next_run,enabled,created_at)`. Foreign tenant checks in methods; do not trust caller IDs. Return records camelCase to JS/frontend; worker never manually assumes snake-case except direct documented SQL.

New account gets seven named agent personas in waiting state, a real empty `Company operations` project for assignment, and a truthful account-created event. No invented work/tests/activity. Frontend wire Agent/Project uses existing model-compatible fields, plus status and backend fields as needed. Never place model API credentials or password hashes in wire state.

## HTTP API

- `GET /api/health` unauthenticated readiness.
- `GET /api/session` -> `{user:null}` or `{user,csrfToken}`.
- `POST /api/auth/register {name,email,password}`, `POST /api/auth/login {email,password}` -> `{user,csrfToken}` + HttpOnly SameSite=Strict session cookie. Password >=12 chars. Constant-time password verification, salted scrypt or PBKDF2, expiry, auth rate limits, body size limits. Mutations require same-origin checks and `X-CSRF-Token`, except register/login which require `X-Requested-With: Attendx` plus same-origin checks. Logout POST `/api/auth/logout`.
- `GET /api/state` -> `{user,agents,projects,reviews,events,tasks,messages,artifacts,memories,skills,schedules,capabilities,metrics}`. Limit response lists, tenant-filter every query.
- `GET /api/events` authenticated SSE; emits `event: change` with safe `{id}` after durable change, keepalive, close on session expiry. Frontend coalesces snapshot refreshes; reconnect with browser EventSource. No token in URL.
- `POST /api/projects {name,brief,scope,team,acceptanceCriteria,budgetCents,repoUrl?}` -> `{project}`. An owner-supplied GitHub repository URL authorizes read-only import for this project, never push/merge.
- `POST /api/projects/:id/plan`, `/run`, `/pause`, `/resume`, `/cancel`, `/verify`; run requires owner-approved plan; pause/cancel affects real work and model abort signals. No arbitrary shell commands supplied by frontend.
- `POST /api/agents/:id/chat {message,projectId}` queues chat and stores user message -> `{jobId}`. Chat may propose actions, not grant permission or invoke arbitrary tools.
- `POST /api/agents/:id/pause` and `/resume` for agent lifecycle.
- `POST /api/agents/hire {projectId,template,name,reason,budgetCents,expiresHours}` provisions only allowlisted templates, <=12 agents per owner, expiring scoped authority and bounded project budget; log real event. A worker can propose hiring through review; cannot change policy.
- `POST /api/reviews/:id/decision {decision:'approved'|'declined'}` checks state, ownership and kind. Plan approval permits run; release approval records reviewed artifact (no automatic public deployment/push); hiring/improvement approvals enforce policy and evaluation conditions again.
- `POST /api/memories {projectId,content,sourceArtifactId?}` owner-approved memory; retrieval scoped to project.
- `POST /api/improvements {projectId,agentId,instructions,fixtures:[{input,expectedIncludes}]}` queues baseline/candidate evaluation (2-6 fixtures); no automatic promotion. Skill promotion requires recorded evaluation and owner approval; rollback `POST /api/skills/:id/rollback` must choose a previously approved version.
- `POST /api/schedules {projectId,intervalMinutes}` creates bounded periodic verification (>=15min, <=6 per owner), no arbitrary URL polling. `POST /api/schedules/:id/toggle`.
- `GET /api/artifacts/:id` -> owner-authorized full artifact; `/download` attachment. Generated HTML preview must be sandboxed, scripts disabled, never injected into app DOM. Artifact content from model is untrusted.

Errors JSON `{error:message}` with correct 4xx/5xx, no internal stack/secrets. All JSON request headers same-origin; no credentialed wildcard CORS. Cross-tenant IDs return 404. Routes must not return success for unavailable capability.

## Worker execution

Export `startWorker(store, options={})` -> `{stop(),cancel(projectId),wake()}`; provider and runner can be dependency-injected in tests. Poll durable jobs with bounded concurrency (2), leases, finite attempts, cancellation, restart recovery. Stop requested state must be checked before and after external calls. Project plan generates JSON `{summary,questions,tasks:[{title,agentName}],acceptanceCriteria}`. Missing requirements become needs_input; complete plan awaits owner approval. Build requests JSON `{summary,files:[{path,content}],runtime:'node'|'python',testCommand:'node-test'|'python-unittest'|'static-check'}`. Import only authorized public GitHub source under fixed HTTPS hosts and strict size/path bounds; private/large/unsupported repos fail explicitly. Repository integration delivers reviewable candidate files/diff and does not push or deploy.

Provider env: `ATTENDX_MODEL_BASE_URL` (default https://api.openai.com/v1), `ATTENDX_MODEL_API_KEY`, `ATTENDX_MODEL` (must be configured), `ATTENDX_MODEL_LOCAL` for no-key local model. Server configured endpoint only; no user-provided fetch URL. Bounded tokens, timeouts, call count, model text treated as untrusted. Reserve conservative `ATTENDX_MAX_CALL_CENTS` (default25) from project budget per call; report as reserved estimate rather than verified provider invoice. No credentials: jobs marked blocked with actionable message, no fake AI fallback. Support local OpenAI-compatible Ollama URL.

Runner request: `POST /run`, header `Authorization: Bearer <control key>`, body `{runId,files:[{path,content}],runtime,testCommand,timeoutSeconds?}` -> `{ok,exitCode,stdout,stderr,durationMs,testCount,files?}`. `GET /health` internal basic status; `POST /cancel {runId}` authenticated. API worker passes stable job ID as runId; cancellation propagates. Broker validates paths/sizes/count/runtime/command; only fixed pinned images and fixed harness scripts. Ephemeral containers are non-root, no network, no capabilities, no-new-privileges, read-only root, writable tmpfs, CPU/memory/PID/time/output limits. No host filesystem bind mounts in jobs. Distinguish zero tests from passed tests. Never allow arbitrary Docker flags, mounts, image names or entrypoints from model/user. Tests assert sandbox flags and malicious inputs without needing daemon, plus real Docker execution test by root.

Build stores generated files, actual test report, source diff/manifest, previewable HTML and release review. A test failure creates a failed result with evidence, never a success badge. Initial self-improvement evaluates baseline/candidate using explicit expected-substring fixtures, records score/cost/latency and warns that these fixtures only cover their stated behavior; promotion gated on no regression and owner approval. Schedules verify existing candidate artifacts using runner without inventing model activity.

## Frontend

Live login/setup, persistent project intake (budget, criteria, repo), office/list/project/task/activity views, agent chat, live events/cost/status, hire controls, memory, improvement evaluation/version controls, schedules, artifacts/test evidence and plan/release approvals. Reuse gray/yellow office assets. Clear missing-model setup with no keys in browser. No simulated counters or animation claiming real work. Motion only reflects active jobs or decorative UI, CSS transforms/opacity, reduced-motion support, responsive and accessible dialogs. Root imports LiveApp from main by default; explicit demo remains available.
